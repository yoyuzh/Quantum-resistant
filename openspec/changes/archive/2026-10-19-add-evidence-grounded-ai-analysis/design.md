# Design

## Context

动机和能力边界见 proposal.md。当前基线为 V1.1.1；扫描器按文件分析，`ScanResponse` 保存 findings、coverage、diagnostics 和 analysis。`TaskStore` 已提供请求幂等、2 执行/4 排队、读者保护、取消、过期及有界暂存；前端通过 `useTaskRunner`、统一请求和短轮询使用任务。

本次代码检查发现两个不能直接套用的内部假设：`TaskStore._run` 根据 sources/repos 是否非空判断成功，并用扫描 coverage 判定 partial；`result(include_content=True)` 会回填源码。AI 成功空结果、独立范围和脱敏快照都需要明确的任务类型适配，不能伪造 sources 来取得成功状态。

现有 `read_job` 能保护短期读取，但长时间持有来源读者会延长大体积扫描暂存生命周期。本方案只在准备有界快照时持有读者，不将来源任务固定到所有 AI 请求结束。

## Goals / Non-Goals

**Goals:**
- 建立可替换模型适配器和严格数据契约，先用单个兼容端点验证整条链路。
- 把可控的候选检索与模型判断分开，暴露两阶段各自的漏报和资源限制。
- 共享现有任务和存储容量，保持旧任务、CLI、报告与风险计数兼容。

**Non-Goals:**
- 不在此变更实现完整跨模块数据流和业务影响图，也不将模型意见自动升级为确认风险。
- 不建立任意模型 URL 代理、浏览器密钥管理、自动模型探活、自动改码或供应商 SDK 体系。
- 不把候选搜索当作完整密码发现；完整基准建设可逐步扩充，但评估工具和首批固定样本在本变更内交付。

## Decisions

### 1. 服务端环境配置和一次性授权预览

新增 `backend/ai/config.py`，读取 `QUANTUM_AI_ENABLED`、`QUANTUM_AI_BASE_URL`、`QUANTUM_AI_MODEL`、`QUANTUM_AI_API_KEY` 及预算变量。BASE_URL 为服务端受信任配置的 API 基址，适配器拼接 `chat/completions`，禁止 query、fragment、userinfo 和重定向；HTTPS 远程地址及 HTTP 回环地址可用。环境代理由服务端控制，不从扫描数据中继承。配置更改重启生效，计算不含秘密的公开配置版本；凭据变化也使服务端内部预览版本失效，但不公开凭据摘要。

使用 httpx 的非流式 Chat Completions 协议，发送 system/user 消息及固定 JSON 输出约束，不强制依赖供应商 JSON schema 扩展。响应从 `choices[0].message.content` 提取并严格 JSON 解析，不从任意文本猜测或修复结构。输出 token 参数的供应商差异由受信任配置确定，首版不自动试探或失败后重复请求。httpx.stream 只用于有界接收 HTTP 响应体，不向模型请求 token 流。

替代方案：浏览器填写任意 URL/密钥、启动时探活、供应商 SDK。它们增加外部访问、秘密暴露和兼容复杂度，首版不采用。

### 2. API 与数据契约

| API | 行为 |
| --- | --- |
| `GET /api/ai/config` | 返回启用/配置有效性、目标 origin、模型、配置版本、有效预算；不联网 |
| `POST /api/ai/previews` | 输入 source_task_id；本地构建有界、脱敏的候选快照，返回 preview_id、digest、有效期、上下文与范围 |
| `POST /api/tasks/ai` | 输入 preview_id、digest、consent=true，要求 X-Request-ID；202 返回 kind=ai 的任务 |
| `GET /api/tasks/{id}` | 复用状态与取消契约，AI 计数放在独立 ai_progress 可选字段 |
| `GET /api/tasks/{id}/result` | kind=ai 返回独立 AiAnalysisResult，不执行扫描源码回填 |
| `POST /api/tasks/{id}/cancel` | 复用幂等取消 |
| `GET /api/ai/tasks/{id}/export` | 下载专用 AI JSON；只允许有结果的 AI 任务，服务端按白名单序列化 |

初步错误映射：来源/预览不存在或过期 404，尚未结束/摘要不符/标识冲突/不支持的任务种类 409，未启用或配置无效 503，非法参数 422，预算外请求 413，队列/预览容量满 429；后台模型鉴权、限流、超时和格式错误映射稳定诊断，不透出响应体。新增写接口接入既有 Host/Origin/JSON 字节边界。

AiAnalysisResult 包含 schema_version、source_task_id、input_digest、created_at、provider/model、规则/提示/核验版本、candidate_coverage、ai_coverage、opinions、diagnostics、usage。静态 finding 引用用来源快照中的稳定指纹，不依赖可变列表下标。Opinion 的 opinion_kind 为 supports_static / questions_static / new_candidate / abstain；citation_status 为 valid / invalid / absent；算法和用途允许 unknown。即使引用有效，所有 AI 意见仍是待人工复核意见。

替代方案：向原 findings 追加 AI finding、修改 ScanResponse 或共用旧报告。它们容易混淆确认风险，首版采用独立任务与专用导出。

### 3. 双路候选与上下文构建

新增 `candidates.py` 和 `context.py`。第一路按 source_id、行范围合并静态发现和 unknown_pem_algorithm 等相关诊断；第二路遍历 Python AST 与 JSON/YAML 配置中的密码线索，不要求静态命中：密码相关未知导入/调用、封装函数中的算法线索、带密钥/加解密上下文的模幂操作、未被确认的算法选择。单独的 pow、变量名或注释不能形成确认风险。词表和规则版本固定，候选排序稳定并按静态/独立两路轮转，避免静态命中挤占全部独立候选预算。

优先截取所属函数、相关导入和邻接代码；超大函数取候选附近的完整行窗口，不把截断标识作为源码。JSON/YAML 使用现有结构化解析能力；其他文件只保留已有发现的局部复核，不宣称独立语义支持。PEM 仅发送已识别头信息和必要用途上下文，不发送密钥正文。不新增执行、安装或导入被扫描包的路径。

候选 ID = 输入快照摘要 + source_id + 位置 + 来源规则的稳定摘要；同一位置两路合并但保留 origins。预览建立行号到脱敏后文本的映射；响应引用只能落在实际发送的行上，不能通过模型引用未发送的邻接代码。

替代方案：只复核 findings 无法测试漏报收益；整仓输入成本、秘密暴露和不可控截断较大。因此采用有界检索，并明确报告检索边界。

### 4. 默认预算与模型响应核验

首版默认：预览最多20个文件、40个候选、总上下文128KiB；每候选上下文最多8KiB且不拆行，实际总量由较先达到的上限决定。独立候选检索至多读取200个受支持文件、合计8MiB源码，按稳定 source_id 顺序；所有可用来源元数据参与跳过统计。候选生成与预览准备共享30秒本地截止。

每模型请求最多5个候选、32KiB输入；任务最多8次模型调用、总时间120秒、单请求30秒、响应256KiB、输出2048 token，全局模型请求并发1。预算值可由服务端在明确硬上限内下调/配置，实际值通过公开状态与预览返回；输入字节限制不能等同于模型 token 数量，供应商上下文溢出作为明确失败，不循环重试。未知 token 用量为 null，不估算真实金额。所有模型调用默认零自动重试，以避免无法判断的重复计费。

`validation.py` 按候选逐项验证结构、唯一标识、枚举、文字长度和引用。非法外层 JSON 使整次响应失败；可解析列表中的单项错误产生该项诊断，其他完整项可保留；遗漏候选计为未完成，不能伪造弃答。原文引用基于脱敏快照逐行核验，不据模型文字确认算法或协议属性。

### 5. 预览、任务和快照生命周期

新增预览管理器，仅保存受限输入和元数据，不保存完整源码。预览TTL为5分钟、最多4份，纳入现有2GiB临时存储；预览总序列化预算2MiB。容量不足返回429或明确存储不足原因，不淘汰正在消费的预览。预览构建使用现有调度器准入执行本地CPU/读取；模型调用期间不占用来源任务读者。

提交时先查询 X-Request-ID 是否已存在，校验 kind、preview_id 和 digest；匹配返回原任务，不要求预览仍存在。新提交再校验确认、摘要、配置版本和TTL，在同一临界区消费预览并把快照所有权移交AI任务；失败回滚预览占用、目录和准入。第二个不同请求标识消费同一预览返回409，主动重新分析需生成新预览。这保证网络重试不造成重复消费，且接纳后的排队不受预览或来源TTL影响。

在 `TaskStore` 增加有限的任务结果策略：扫描与热门沿用现有判断，AI根据“计划候选是否全部完整处理、是否主动取消、是否有完整项”决定状态。零候选为 succeeded 并记录范围；全部显式弃答为完整分析；模型未返回或格式失败为未完成；部分完整项且中止为 partial。AI-specific progress 不复用 scanned_files。终态冻结在持锁状态转换中完成。

AI任务独立快照和结果遵循终态15分钟、8份、512MiB结果预算及共享清理。模型请求设短读超时并检查取消；取消不能撤回已发送数据，后续批次必须停止，残缺/迟到响应不得进入已冻结结果。源文件过期后保留AI结果中的有限脱敏证据片段，完整源码跳转提示不可用。

替代方案：第二套任务队列破坏容量约束；持有来源大目录直到分析结束影响清理；借用 sources 字段伪造成功污染契约。因此只扩展必要任务类型钩子，复制有界快照。

### 6. 前端与验证

新增 `AiAnalysisPanel.vue`、`AiOpinionList.vue`、`AiPreview.vue` 及 `useAiAnalysis.js`，挂接在普通扫描结果。预览明确显示目标、脱敏片段与字节数，提交按钮表示本次主动同意；不设置持久化的默认勾选。composable复用统一请求和状态轮询，按source_task_id隔离；刷新只保存AI任务ID，不在浏览器存储源码或凭据。

纯函数负责意见过滤与展示，组件不使用 v-html。点击引用联动既有 source_id 源码定位；无完整源码时显示快照片段。静态结果数值不变，AI标签用“支持/质疑/新候选/无法判定”和“引用有效/无效”，避免“已验证安全”。

新增 `tests/fixtures/ai/` 固定开发/测试清单、正负样例和模型响应；不得执行样例。`scripts/evaluate_ai.py` 离线评分四组已保存预测，按位置+算法+操作匹配，一份真值最多匹配一次；跨项目划分并记录同源样例关系。首批覆盖别名、未知调用、封装、数学负例、注释指令、PEM脱敏、同名路径、无证据和弃答。Precision/Recall只在明确标签范围内报告；候选阶段和最终意见阶段分别度量。

自动测试模型HTTP使用mock；浏览器本地fixture通过真实路由、任务与适配器配合本地受控模型响应验证。真实供应商连通与效果验收在配置可用后另行执行并记录，不把mock宣称为实网验证，也不在未确认发送的情况下自动探活。

## Risks / Trade-offs

- [有限候选漏报] → 报告检索文件/字节边界，独立测量候选召回，抽查未命中文件；不承诺完整覆盖。
- [模型幻觉与错误否定] → 强结构、逐项引用核验、弃答、原结果隔离；引用有效不等于语义正确。
- [秘密与提示注入] → 受信配置端点、禁止重定向、脱敏预览、不提供工具、最小上下文；脱敏有局限需用户检查。
- [取消与计费] → 单次及总超时、零隐式重试、请求幂等、迟到丢弃；已发送请求可能仍产生供应商费用。
- [现有TaskStore回归] → 分离任务结果策略，保留扫描/热门回归，并验证成功空结果和清理竞态。
- [模型协议差异] → 固定首版兼容协议与明确错误，不自动更换模型或参数重发。

## Migration Plan

按tasks.md先建立契约与离线测试，后接入模型、任务、UI与评估。默认关闭AI，现有安装无需配置即可运行；启用需要设置环境配置并重启，每次分析经预览提交。此流程不需要数据迁移，不改变已有报告。

回滚通过关闭AI配置或撤销此变更，仍能静态扫描；取消运行AI任务并清理新增暂存目录，旧任务清理约束不变。本提案不授权commit、push、部署或真实模型调用。
