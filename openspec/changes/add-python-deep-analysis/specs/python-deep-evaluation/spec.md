# Spec Delta

## Purpose

以人工标注的共同输入和固定正确性标准验证引擎复用、密码语义及证据链，分别计量上下文操作、算法和传播边，确保技术选型、性能数字及发布声明来自可重现的当前证据。

## ADDED Requirements

### Requirement: 至少30个共同标注夹具

系统 SHALL 建立至少30个不执行的手工标注多文件案例，含输入/路径/source_id、支持版本、预期操作上下文、算法/类型、证据边和Unknown原因。覆盖导入/相对路径/别名、参数/关键字/默认、返回/重赋值/分支、两上下文、同名模块、密钥接收者及动态/递归/缺导入/PEM反例。支持范围和标签在锁定测试前冻结，复制变体不跨开发/锁定集。

#### Scenario: V-01 两上下文金标准
- **WHEN** 同一包装存在RS256和HS256两条预期操作而仅识别一条
- **THEN** 操作级计一条TP和一条FN，不能因定位到底层函数就算全部召回

### Requirement: 选型验证前置

正式索引和数据流生产依赖冻结前 SHALL 使用同一夹具、输入映射与预算对Scalpel、CodeGraph及受限AST路线做能力矩阵，记录版本/commit/许可、安装、语法、源位置、调用/值流、错边/Unknown、取消/隔离、打包、耗时/RSS/磁盘。先核对原始来源再接受调研结论，不以调用图当值证明。候选不适用 SHALL 使用受限AST回退；CodeQL仅在授权允许且可用时独立对照，缺失注明未测。

#### Scenario: V-02 框架无位置或串值
- **WHEN** 候选有调用图但无精确span或混淆两次调用的算法
- **THEN** 不让其直接产出已证明算法，只复用通过的模块或选择回退，并保存选型理由

### Requirement: 一对一指标和未知分母

评测 SHALL 按同快照sink精确span、操作类型及上下文确定一对一稳定匹配，重复预测为FP，模板定位另计。算法/参数正确率、逐类型边正确率、错误E3及Unknown/覆盖缺口 SHALL 单列；错误算法不算端到端正确操作。Unknown/超限导致漏报仍计FN，不删掉失败样本，支持范围内外分开报告，零分母null。

#### Scenario: V-03 错算法与预算截断
- **WHEN** 一条操作定位正确但算法错误，另一金标准因预算未分析
- **THEN** 不将两者算端到端正确，截断样本仍留召回分母并说明缺口

### Requirement: 正确性门槛与真实试点

首版 SHALL 在人工锁定基准中达到错误高等级证据0、跨调用串值0、原源码改写0、未授权外发0；支持范围内端到端操作Precision>=95%、Recall>=90%，报告样本量/TP/FP/FN与区间，不能把工程门槛说成已有成绩。正确性通过后才评性能，至少一个许可允许、固定版本/内容的真实仓库只读试点，先冻结人工审查范围；非完整审查不得宣称全仓召回。

#### Scenario: V-04 小样本或未人工审查
- **WHEN** 合成测试通过但真实仓库未完成标注
- **THEN** 分开记录夹具通过与试点未完成，不外推全生态准确率或伪造独立人工金标准

### Requirement: 集成故障与当前验收证据

验收 SHALL 包含四输入/basic兼容、模式/幂等、快照链接/路径/摘要攻击、超时/取消/迟到、源清理/存储满/写失败/第三方退出、评分/CLI/旧四报告回归，以及真实本地FastAPI+Vue页面/导出。远程回归mock，不执行sample_inputs风险样例。记录命令、环境、摘要、版本、日志和截图；规划及历史记录不代填实现验收。

#### Scenario: V-05 旧测试通过但新功能未运行
- **WHEN** 只有旧扫描测试或历史AI记录
- **THEN** 新静态深度验收仍标未执行，不宣称完成、发布或已验证第三方能力
