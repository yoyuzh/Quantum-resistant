# Design

## Context

`backend/popular.py` 的 `scan_single_repo` 从完整基础发现计算算法集合和总数，随后只将前 20 条发现写入热门列表。增强任务通过 `backend/popular_analysis.py` 保存逐仓详情，并在融合投影阶段更新摘要。`integrated_analysis.findings` 是最终去重的记录集合，已有判断状态、有效用途、用途来源和发现标识。单仓库报告依赖另一种请求模型。全景图和批次清单均以热门页实际拿到的终态结果为输入。

## Goals / Non-Goals

让用户先定位涉及某种算法的仓库，再核对用途、证据和迁移参考；让离线读者取得同批完整的逐仓盘点。统计单位为发现记录、去重仓库两种。本期沿用现有采样入口、扫描预算和单进程快照生命周期，跨仓调用或依赖关系不在采集范围内。

## Decisions

### 1. 在仓库摘要保存分组和少量可定位证据

给仓库结果增加可选的 `algorithm_inventory`。存在时包含分析口径（基础或融合）、已评估的判断来源、分组及计数。分组键采用算法、有效用途、用途来源、判断状态。每个非空分组最多保留一处可定位示例，按仓库相对路径、行号、发现标识稳定选取，保存来源标识及可用的发现标识。用途未知单独成组。只从允许的元数据字段构造示例。

基础模式在截断前计算，仅能评估基础静态发现。增强模式在已有逐仓融合投影处从最终记录重算并替换整份摘要，后续 AI 补充或任务重试也遵循同一规则。覆盖范围由独立的 coverage 字段描述。这样仓库列表、排行和文档均可从一次批次读取完成，打开页面时无需逐仓下载源码或融合详情。

### 2. 区分零、未知和部分扫描

对于已评估来源，没有相应分组表示该仓库已扫描范围内计数为零。没有运行的阶段标为「未评估」，阶段只完成一部分时展示已有数并注明阶段覆盖。缺少新版摘要时从 algorithms 字段展示基础算法集合；finding_count 仍是历史基础总数。算法覆盖的分子是当前口径下检出该算法的不同仓库数，分母是具备该口径结果的可用仓库数；标明其中部分扫描数。历史基础检出和融合静态确认分别标注。保留原有扫描失败列表和批次未完整结束标志。

### 3. 入口放在热门页，图和表使用同一批次数据

资料库直接展示可操作的仓库—算法关系图，热门页在批次对话框里复用同一视图。仓库与算法分别位于左右两列，正数分组形成连线，连线在同一来源下共用全库线性刻度，保留最小可见线宽。历史检出仅表示存在关系。节点携带计数，未连线仓库列出扫描状态。以原生 SVG 呈现证据图风格的节点及曲线。左右区内轻微错位、浮动，支持单节点拖动和双指缩放。聚焦时邻居同步靠拢至视野中央，其余节点和边淡出，减少动态效果时直接切换。可用键盘选择节点与对应证据。窄屏使用简短节点名，详情保留全名。

复用单仓库详情加载以及证据组件，按仓库身份、算法和判断来源过滤；有适用关系时呈现「文件 → 算法用途 → 迁移参考」。任务到期后仅展示摘要内已存的位置。热门页只按需打开一个仓库的详细结果。

### 4. 下载整批 Markdown 清单

用前端纯函数从同一个批次视图模型生成清单，导出输入取筛选前的批次。使用浏览器本地下载，文件名按扫描时刻生成，如 `多仓库密码算法清单-YYYYMMDD-HHmmss.md`（北京时间）。时间缺失时以「时间未知」命名。Markdown 便于离线评审、版本比较，也容纳逐仓说明及嵌套明细。无需给现有单仓库报告接口增加另一套输入类型。

| 文档章节 | 读者可核对的内容 |
| --- | --- |
| 批次概况 | 软件名称、时间、查询条件、请求/可用/部分/失败数、未完整结束标志及范围说明 |
| 算法覆盖 | 每种算法按判断来源列出检出仓库数、可比较分母与记录数；旧摘要的基础检出单列 |
| 逐仓清单 | 仓库全名和链接、覆盖、文件数、优先级分数；分组表逐行写算法、用途、用途来源、三类记录数及各非空组的代表位置 |
| 失败或未完成 | 每仓一行，附可展示的失败原因；没有失败时写明数量为零 |

先按项目既有脱敏规则整理可展示原因，再对外部文本做 Markdown 文本和表格转义；仓库链接仅使用已验证的 GitHub 仓库地址。路径以仓库相对位置输出。同批同数据的章节和行次稳定，以便人工核对。

## Risks / Trade-offs

- 只分析了部分文件或部分候选 → 图和清单同时标明覆盖及阶段状态，分母可复核。
- 历史快照仅有明细样例 → 保留基础算法集合和总量，分布和位置按可用程度展示。
- 聚合会丢失逐条解释 → 每个非空分组保留一条可用位置，活跃任务可下钻到完整详情。
- 失败或超时批次覆盖此前完整快照 → 沿用既有完整性判断和原子保存，当前批次仍可导出。

### 5. 软件内置初始数据，本机保存增量后的资料库

初始样本为 30 个人工选择的公开仓库，按固定提交下载归档，用本项目基础静态扫描器分析。首轮每仓最多采集 350 个文件，随后对部分覆盖的仓库按同一提交和 5000 文件上限补扫，保留单文件大小和编码限制。桌面构建显式包含同一份只读种子。读取时用种子补齐本机资料库缺少的仓库，发生新增或更新后在桌面用户数据目录（源码版为 web/data）原子写入完整本机资料库。热门批次快照独立保存。

资料库 JSON 只包含逐仓摘要和可用的提交标识，全景图和 Markdown 使用同一份记录。导入校验文件版本、字段、路径和规模，全量通过后按 GitHub 仓库全名忽略大小写合并。按实际扫描时间择新，同一时刻保留本机记录。追加扫描默认跳过已有仓库，显式更新时用新结果替换；失败仓库保留原有记录。单次扫描最多 30 个，累计数据分页展示。

### 6. 按仓库主要用途折叠和展开

六个内置分类用仓库全名映射，支持大小写差异，未知仓库归入待分类。图的左、中、右分别为类别、仓库和算法。默认按分类汇总算法计数；展开时所属仓库从类别节点移入中列，等宽归属线随节点展开，镜头聚焦当前类别及关联算法。当前页的逐仓检出连线替换该类别汇总线。定量线宽以当前判断来源下全库最大分类与算法分组计数为刻度上限，筛选和分页共用此刻度。分类为展示层元数据，旧 JSON 和本机存储格式继续适用。Markdown 用同一分类分节，包含全部逐仓记录。

## Migration Plan

先增加可选仓库摘要并验证新旧结果均可读取，再接入图和清单。无需回填历史快照。若撤回界面，旧客户端继续使用原有仓库字段。
