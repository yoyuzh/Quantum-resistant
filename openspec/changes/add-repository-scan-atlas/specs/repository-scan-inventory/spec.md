# Spec Delta

## Purpose

让接手批次评审的读者在离开系统后，仍能从一份中文清单了解样本的选择方式、逐仓扫描范围、算法与用途计数、可核对的证据位置和数据缺口，并能与同批全景图逐项核对。

## ADDED Requirements

### Requirement: 资料库交换与合并

系统 SHALL 提供可离线使用的版本化 JSON 数据包，支持导入后接续扫描。合并以不区分大小写的仓库全名为键，采用较新扫描结果，同一时间保留本地记录。写入失败或数据包无效时须保留原库。

#### Scenario: 在另一台设备继续积累
- **WHEN** 目标设备导入包含新仓库与重叠仓库的资料库，再次导入相同文件
- **THEN** 新仓库出现一次，重叠仓库使用较新记录，重复导入保持计数一致，仍可导出 JSON 和 Markdown

### Requirement: 导出完整批次的独立文档

系统 SHALL 提供「导出批次清单」，生成 UTF-8 Markdown，注明软件名称、北京时间扫描时间、样本条件和统计口径。文件须包含批次概况、算法覆盖汇总、逐仓清单和失败或未完成仓库。每个请求到且可识别的仓库均有结果或失败说明。用户可在离线环境阅读。

#### Scenario: 筛选后下载清单
- **WHEN** 当前图只显示检出 RSA 的仓库，用户导出本批清单
- **THEN** 文件按仓库用途分类列出全批仓库，算法覆盖和分母与清除筛选后的同批图一致，文件名包含批次时间

#### Scenario: 批次只有失败结果
- **WHEN** 有终态批次但可用仓库数为零
- **THEN** 清单写出请求数、可用数、各项已知失败原因；算法汇总提示无可用结果

### Requirement: 逐仓记录与证据可核对

文档 SHALL 给出仓库全名、仓库链接、扫描状态、已扫描文件数、可用的候选文件数、迁移优先级评分及其启发式含义。对有分组数据的仓库逐项列出算法、用途、用途来源和三种判断来源的记录数。有可定位记录的非空分组须附代表性证据及该组总数，注明示例范围。证据使用仓库内相对路径与行号。

#### Scenario: 分组含多条证据
- **WHEN** 某仓库 RSA 签名分组有 21 条静态确认记录
- **THEN** 清单写出该组静态确认 21 项，并附已保存的代表位置；读者能分辨示例数与该组总数

#### Scenario: 历史快照或扫描未完整结束
- **WHEN** 导出部分扫描或旧格式快照，缺少覆盖范围、分组数量或证据位置
- **THEN** 保留已知范围、基础检出和可用计数，将缺失项标为未知或不可用，写明部分扫描或批次未完整结束的状态

### Requirement: 导出使用当前结果

系统 SHALL 使用当前可见批次已有的数据生成清单，沿用本批图表的统计口径。文档只收录可公开展示的扫描元数据、计数及相对位置。

#### Scenario: 任务清理后离线导出
- **WHEN** 浏览器已有批次快照且任务详情不可用
- **THEN** 下载成功，无须重新采集仓库或调用模型；文档内无源码正文、模型密钥、本机临时路径或失效的任务链接
