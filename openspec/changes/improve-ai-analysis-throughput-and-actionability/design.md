# Design

## Context

当前 AI 预览会把静态发现和独立检索位置按行合并，示例仓库中的重复 `rsa.generate_private_key` 调用形成大量近似候选。默认批次为 5、单任务最多 8 次调用、总截止时间为 120 秒；真实模型响应较慢时会产生重试并提前结束。现有结构化意见已经包含算法、用途、依据、缺失信息和引用，但没有稳定的迁移建议字段。详见 proposal.md 和本变更的三份 Spec Delta。

## Goals / Non-Goals

**Goals:**

- 在发送模型前合并语义等价的重复候选，同时保留全部原始行定位。
- 使用有限的局部上下文提高用途判断质量，并准确报告上下文缺口。
- 在预算内提高每任务完成候选数，保留可靠的 partial 结果和超时诊断。
- 让模型在有证据时输出迁移方向、适用条件和人工核查项。
- 记录真实供应商 usage；缺失时保持未知。
- 通过 mock 自动测试和受控真实模型验收验证吞吐、引用和意见质量。

**Non-Goals:**

- 不把 AI 意见改写为静态 findings，也不自动修改用户代码。
- 不实现完整跨模块、跨语言或运行时可达性分析。
- 不把模型自报置信度当作风险概率。
- 不在自动测试中访问真实供应商。
- 不改变普通扫描默认关闭 AI 的行为。

## Decisions

1. **候选采用两阶段、保守的语义分组。**
   - 先保留现有 `(source_id, line)` 位置级合并，再以 `source_id + rule/API + 规范化参数 + 作用域指纹 + 用途指纹` 做语义分组。
   - 用途未知或使用证据不等价时不得跨位置合并；每组保留代表候选、全部成员位置和静态 finding 引用，使用稳定摘要生成候选标识。
   - 选择局部区域聚合而不是按整个文件合并，避免把签名和解密等不同用途错误合并。
   - 备选方案：仅按连续行去重，实现简单但无法处理间隔重复；全文件按 API 合并则存在语义错误风险。

2. **上下文按证据优先级扩展，不执行源码。**
   - 按 P0 API/静态证据、P1 赋值目标及直接使用、P2 函数签名/import、P3 直接调用方、P4 配置和附近代码排序选择上下文；超过预算时按稳定顺序截断并写入 skip reason。
   - Python 只建立轻量定义—使用索引；变量重赋值或分支无法确认时标记 `confirmed_local`、`possible` 或 `unknown`，不冒充完整数据流事实。
   - 继续使用脱敏后的快照，引用校验基于发送快照。
   - 备选方案：发送完整文件，信息更全但会放大隐私、请求大小和延迟风险。

3. **输入、输出和时间共同决定批次。**
   - runner 以 `min(B_input, B_output, B_time, B_max)` 形成批次：同时估算输入字节、结构化输出余量、剩余任务时间、排队和重试退避。
   - 初期使用输出保守余量和历史耗时滑动估计，不引入复杂预测器；区分全局 provider 失败和局部批次格式失败。
   - 保留最大调用次数、单请求超时、总任务截止和全局并发限制。
   - 备选方案：只延长总超时，无法解决重复候选和单次响应过大的根因。

4. **迁移建议作为可选字段并独立校验。**
   - 增加 migration_direction、applicability 和 manual_checks 等字段，只有模型提供且通过长度、用途/算法兼容性和引用校验时才展示。
   - 将 `citation_status=valid` 与 `migration_validation=needs_review|accepted|invalid` 分开；例如 RSA 签名到 ML-DSA 可作为有条件方向，RSA 加密到 ML-DSA 应标记用途不匹配。
   - 没有充分证据时使用 unknown/abstain，不生成默认迁移结论。
   - 备选方案：从算法名称在服务端自动拼接建议，容易掩盖用途和部署场景差异。

5. **usage 采用供应商原样可验证映射。**
   - provider 只读取标准 usage 数值并写入结果；缺失或格式不完整时保存 null 和诊断。
   - 不从字符数估算 token。
   - 备选方案：本地 tokenizer 估算会与供应商计费不一致，且无法覆盖自定义代理。

6. **先建立固定基线，再比较改造收益。**
   - 固定重复调用与不同用途反例，记录候选数、完成数、请求数、耗时、引用有效率和迁移建议证据率。
   - 通过 A 基线、B 仅聚合、C 聚合加上下文、D 完整方案四组消融实验区分性能和质量收益。

## Risks / Trade-offs

- [Risk] 聚合可能合并本应分开的不同用途调用 → 只合并相同 API、相邻上下文和等价参数；保留原始位置并允许人工下钻。
- [Risk] 批次增大导致请求超时或响应超限 → 发送前估算字节数，设置上限并在剩余截止时间不足时提前停止。
- [Risk] 迁移字段被模型泛化 → 必须绑定有效引用、保留适用条件和人工复核状态，不影响静态评分。
- [Risk] 本地模型代理继续不返回 usage → 明确显示未知，并在验收报告中把用量列为未验证。
- [Risk] 代表候选的有效引用被误当成全部成员都已独立验证 → 结果同时保存成员映射和代表范围，迁移意见只绑定聚合组并标记需要人工复核。
- [Risk] 真实模型结果难以稳定回归 → 保存脱敏候选摘要、版本和结构化响应摘要；自动回归仍使用固定 mock。

## Migration Plan

1. 先建立固定基线和语义错误反例。
2. 实现位置到语义组的保守映射，再实现证据优先级上下文。
3. 增加 provider/runner 的输入/输出/时间联合批次、截止时间和 usage 记录。
4. 扩展结构化意见及独立迁移建议校验。
5. 运行四组消融实验、Python 和前端完整回归，再执行本地 `.env` 模型受控验收。
6. 若真实模型出现超时或格式问题，可通过配置恢复旧批次和预算；不需要回滚静态扫描或历史结果。
