# Spec Delta

## MODIFIED Requirements

### Requirement: 取消超时与终态
状态 SHALL 区分准备、候选、模型分析、核验阶段及实际完成计数。候选聚合后，重复且语义等价的调用位置 SHALL 共享一个可定位候选，避免在同一任务中重复发送相同证据。取消或超时 SHALL 阻止后续调用，释放资源并保留此前完整处理的候选结果；未完整响应不得视作有效意见。终态 SHALL 明确计划候选数、已完成数、跳过数、实际请求数、重试数和未完成原因。AI 失败不改变来源扫描结果。

#### Scenario: 重复调用聚合
- **WHEN** 一个文件包含多处相同密码 API 调用且上下文与参数等价
- **THEN** 预览显示聚合后的候选数量，并保留每个原始位置的可回溯引用，不为每一行重复发送独立请求

#### Scenario: 模型慢导致截止时间
- **WHEN** 模型请求在总任务截止时间前无法完成
- **THEN** 系统停止后续请求，保留完整意见，状态为 partial，并报告已完成、未完成、超时和重试数量

#### Scenario: 部分完成后取消
- **WHEN** 已处理一个候选且第二个模型请求进行时用户取消
- **THEN** 不再发起后续请求，只保留完整结果并标为 partial，迟到响应不改变终态

#### Scenario: 取消前无有效结果
- **WHEN** 首次响应未完成时取消
- **THEN** 状态为 cancelled，不把残缺响应展示为已分析结果

### Requirement: 独立结果界面与导出
页面 SHALL 分别展示静态结果和 AI 意见，列出算法、用途、意见类型、引用核验、来源、模型/版本、范围及未完成原因。对证据充分的意见 SHALL 展示迁移方向、适用条件和下一步核查项；对证据不足的意见 SHALL 展示 unknown/abstain 及缺失信息。专用 AI JSON 导出 SHALL 包含结构版本、输入摘要、原静态发现引用、AI 意见、核验、范围、请求/重试计数和诊断。

#### Scenario: 意见包含迁移建议
- **WHEN** 模型确认具体算法并提供证据
- **THEN** 结果展示与该算法对应的迁移方向和适用条件，且不把建议当作已执行的代码修改

#### Scenario: 意见缺少上下文
- **WHEN** 模型无法确认调用用途或可达性
- **THEN** 结果保留 unknown/abstain、缺失信息和人工核查项，不生成确定性迁移结论

#### Scenario: 导出包含质疑和新候选
- **WHEN** 用户导出 AI 分析结果
- **THEN** JSON 分别保留原始发现引用和 AI 意见，不将新候选列为已确认风险，不含完整源码或模型凭据
