# Python 深度分析正确性专项优化计划

## 目的

本轮优化针对当前锁定矩阵的严格端到端指标，不通过删除困难样例、放宽未知值或修改标签来提高分数。每次改动同时保留历史矩阵，并生成新的矩阵与差异说明。

当前基线：支持范围内严格端到端为 27 TP / 4 FP / 4 FN，Precision 和 Recall 均为 87.10%；操作定位为 33 / 0 / 0，算法 claim 相对现有标签的错误 E3 为 0。四个支持范围内差异来自 Unknown 原因或条件表示，另有 `decorated` 和 `unsupported_config` 两个范围外差异。

## 第一阶段：结果语义规范化

1. 建立稳定的 Unknown 语义分类，将递归、未知分支、不可支持函数、不可推导值和运行时配置分别归类；内部诊断原因仍保留在 diagnostics 中。
2. 将分支条件从不透明哈希转换为“条件位置 + true/false”的可比较表示，避免同一语义条件因生成方式不同被计为 FP/FN。
3. 将评测拆为语义匹配指标和诊断原因指标。主 Precision/Recall 比较操作位置、上下文、算法状态和候选值；原因名称单独报告，不能因内部命名变化掩盖算法值错误。
4. 先对四个支持范围内差异进行独立人工复核，再重新冻结指标；未经复核不得改写历史标签。

## 第二阶段：真实仓库召回优化

1. 增加类方法中的 JWT/PyCA 调用夹具，修复类方法作用域、`self` 参数和跨方法调用链的静态传播。
2. 对透明装饰器继续分析函数体；未知装饰器保留候选并降级证据等级，不把函数静默丢弃。
3. 增加运行时配置字段、分支缺失值和递归包装的真实样例，保持无法证明时返回 Unknown。
4. 重跑 Microblog v0.23 固定内容试点，并对两处预审 JWT 调用逐项人工裁决；不以单文件结果推断全仓召回。

## 验收门槛

- 历史矩阵文件不覆盖；新矩阵记录 schema、代码版本、夹具摘要和人工审查状态。
- 支持范围语义指标达到 Precision ≥ 95%、Recall ≥ 90% 后，才进入性能和发布评估。
- 错误 E3、串值、源码改写和未授权外发继续由独立测试验证；诊断原因归一化不能替代这些检查。
- 全量 Python 回归、前端测试、构建和本地 HTTP 验收必须通过。

## 本轮首次改动的临时观察

已实现 Unknown 原因和分支条件的语义规范化，并增加类方法模板发现回归。使用同一历史夹具、同一标签和新评测代码重算时，支持范围内严格端到端临时结果为 30 TP / 1 FP / 1 FN，Precision 和 Recall 均为 96.77%；完整锁定集为 31 TP / 2 FP / 2 FN。该结果仍是工程对比数据，不是最终验收结果：标签尚未独立人工裁决，`branch_unknown` 的备选值差异和 `unsupported_config` 的范围外差异仍保留，真实仓库试点尚未重跑。
